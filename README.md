# CT小舖御用機器人

Discord 接單機器人：開單、付款、狀態公告、結單、工單排序。

## 部署
- `Procfile`：`worker: python bot.py`
- 環境變數：`DISCORD_TOKEN`（必填）；`DB_PATH` 可選，建議指到持久化磁碟。
- 機器人需要的權限：管理頻道、管理身分組、查看頻道、發送訊息、管理訊息、讀取歷史訊息、附加檔案、嵌入連結。
- 啟動時只會保留各伺服器的指令，並清掉殘留的全域舊指令。
- 機器人目前只適合**單一伺服器**使用：商品庫存與會員餘額是全機器人共用（資料表沒有伺服器欄位）。

## 工單排序（`/自動排序工單號`）
- 依工單開啟時間由早到晚連號：0001、0002…
- 幣號工單進「幣號工單」系列分類，代肝工單進「代肝工單」系列分類（沒有會自動建立），每個分類最多 50 張。
- 「服務中」分類內的工單、名稱沒有工單號的頻道完全不動。
- 結單分類不搬動，但內部依工單號排序。
- 頻道改名被 Discord 限速（同頻道 10 分鐘 2 次）而失敗的工單，保留舊號與原分類，稍後再執行一次即可。

## 開單訊息
- 新工單第一則：歡迎訊息（可用 `/設定工單訊息` 修改）＋ 🔒 關閉工單按鈕。
- 第二則：購買服務面板；`/停止發送面板` 可關閉、`/開啟發送面板` 恢復。

## 商品與服務
- 幣號規格：`100M（普通）`、`100M（不死）`（價格、最低購買數量、庫存用 `/設定價格`、`/設定最低購買數量`、`/設定庫存` 設定）。
- 服務：幣號、代肝、**A大子彈**（單位「發」，不限庫存，價格與最低購買數量同樣用上面的指令設定，商品選「A大子彈」）。
- 子彈工單頻道名稱：`狀態-子彈-工單號-數量發`；排序與結單時與幣號共用同一串分類。`/改名工單 子彈` 可手動改名。

## 免洗帳號
- `/上架帳號`：先選「幣號規格」，「登入方式（Garena／Google）」**選填**（不選＝未指定登入）。可一次貼很多組，組與組之間用 `—————` 分開，機器人自動拆成一隻一隻；也可上傳 .txt（有分隔線就依分隔線拆，沒有就一行一組；欄位用 `----` 分隔）。
- `/帳號庫存`：各規格、各登入方式（含未指定）的可發／已發數量。
- `/帳號庫存總表`：把庫存裡所有「可發」的帳號直接列給管理人員（只有你看得到，同時附 .txt 檔）；不會標成已發，也不用走發貨。可選填「商品」只看某規格；組數太多時只給檔案。帳號是明文，只有店長等級可用（客服身分組不行，和 `/匯出資料庫` 相同）。
- `/發號`：登入方式可選可不選（不選＝從庫存足夠的登入方式（含未指定）中隨機挑一種），從庫存取帳號發給這張工單的客人；每組帳號只會發一次，發完訂單改為待收貨。
- `/設定發號訊息`：自訂跟帳號一起發出的說明（可選「全部」或個別登入方式；可用 `{客人}` `{商品}` `{數量}` `{登入方式}`）。
- `/發號紀錄`：這張工單發過哪些帳號。
- `/設定低庫存提醒`：某規格＋登入方式剩幾組以下就在操作紀錄頻道提醒補貨（預設 3，0＝關閉；用完一定提醒）。`/帳號庫存` 會用 ⚠️ 標出偏低項目。
- 帳號內容以明文存在資料庫，請把 `DB_PATH` 指到安全的持久化磁碟。

## 工單號管理（`/工單號`）
- `/工單號 查看`：看計數器、現存最大號、下一個要發的號碼。
- `/工單號 設定`：手動指定下一個工單號（必須大於現存最大號）。
- `/工單號 同步`：把計數器對齊成「現存最大號 + 1」。
- `/工單號 本頻道`：替還沒有工單號的頻道發號並改名。
- 注意：`/發號` 是發免洗帳號，工單號管理改用 `/工單號`，兩者不要混用。

## 餘額
- 店長：`/增加餘額`、`/扣除餘額`（可加備註；單次上限 NT$10,000,000）、`/餘額總覽`。權限是「店長」等級（客服身分組不含）。
- 會員：`/查詢餘額`、`/餘額紀錄`（看自己的；店長可看任何人）。
- **餘額付款**：客人在付款方式面板按「💰 使用餘額付款」→ 二次確認 → 一次扣款，系統自動確認付款，進「待交貨」（代肝進「待排單」）。餘額必須足夠付清整張訂單，不與其他付款方式合併。
- **取消自動退款**：用餘額付的訂單被改成「已取消」會自動退回餘額（重複取消不會重複退）。已到「待收貨」或「結單」不自動退，請店長手動 `/增加餘額`。

## 營業狀態
- `/暫停接單`：客人無法建立新訂單（已建立的不受影響），會看到「暫停接單提示」（`/設定訊息`）加上 `/設定店長公告` 的內容；`/恢復接單` 解除。
- `/店長狀態`（營業中／休息中）只是狀態標示，不會擋下單。
- `/設定補貨時間` 設定的時間，會顯示在「缺貨／暫停提供」的提示裡。

## 備份與還原
- 機器人每 6 小時自動備份一次資料庫，保留最近 3 份（`DB_PATH` 同目錄的 `.bak1` 最新）。
- `/匯出資料庫`（店長）：下載整個資料庫（zip，內含 `trade_bot.db`），並私訊一份；備份含帳號明文，請妥善保管。
- 還原：先停止機器人，把 `trade_bot.db` 放回 `DB_PATH` 的位置再啟動。
- `/訂單操作紀錄`：看這張工單的訂單被誰在何時確認付款、發號、改狀態。

## 測試
- 改程式後先跑：`python3 test_bot.py`（不需要 Discord 與網路），涵蓋餘額付款與退款、庫存退回、暫停接單、資料庫匯出等。

## 版本規則
每次修改程式就把版本號 +1，壓縮檔名同步更新（目前：CT_Shop_V172.zip）。

## 更新紀錄
- **V172**：撤回 V171 對發號與上架帳號的修改，發號訊息的符號與上架拆分方式維持 V170 的樣子，沒有任何改動。
- **V170**：新增抽獎功能（按鈕參加、店長手動開獎、獎品為文字由店長自己發）。
  - `/建立抽獎 獎品 [名額] [說明] [頻道]`：發出抽獎訊息，客人按「🎁 參加抽獎」（每人一次，可自行退出）。
  - `/開獎 編號`：隨機抽出得獎者並公布，只能開一次；已離開伺服器的人不會被抽到。
  - `/重抽 編號 [人數]`：有人棄權時補抽，不會抽到已得獎的人。
  - `/取消抽獎 編號`、`/抽獎列表`：取消、查看進行中的抽獎。
  - 以上指令只有管理員能用；建立、開獎、重抽、取消都會寫進操作紀錄頻道。
- **V169**：移除開單時一段永遠不會執行的檢查；開單分類是「服務中」時，`/自動排序工單號` 的提示文字改成不會誤導。
- **V168**：`/設定開單分類` 現在可以選名稱含「服務中」的分類（新單一開就算服務中）。此時「服務中」內的工單照舊不被排序改名換號，`/自動排序工單號` 也不會把其他工單搬進服務中；滿 50 張自動往下開新分類的機制照常運作。
- **V167**：清理。移除沒用到的變數與測試檔裡永遠不會執行的一行；全檔掃描確認沒有多餘的 import、函式、常數、註解掉的舊程式碼。功能不變。
- **V166**：新增 `/帳號庫存總表`（店長等級）：直接把全部可發帳號列給管理人員，不用發貨、不改狀態。
- **V165**：V164 的除錯。修正多行帳號（例如「帳號：x」換行「密碼：y」）發號時欄位擠在同一個區塊、無法分開複製；現在換行也會當欄位分隔，帳號與密碼各自一個框。補上對應測試（共 33 項）。
- **V164**：`/上架帳號` 改版。
  - 一次上架很多隻：組與組之間用 `—————`（3 個以上長橫線，或單獨一行的 `-----`）分開，機器人自動拆成一隻一隻；沒有分隔線時一行一組。回覆會顯示「拆成幾組／上架幾組／重複略過幾組」。
  - 登入方式改成選填（不選＝未指定登入），參數順序：商品 → 登入方式 → 內容 → 檔案。未指定的帳號會出現在 `/帳號庫存`，`/發號`、「🚚 發貨」不指定登入方式時也會納入隨機挑選。設定匯入也接受未指定登入。
- **V163**：修正「別人開的工單變成店長的」。
  - 原因 1：自動辨識工單客人時，沒有排除店長（`ticket_owner_id`，開單時 bot 會把店長以個人權限加進每張工單）與店長／闆闆👑 等管理角色，而且還「優先挑闆闆👑」，結果店長常被當成客人。現在這些人一律視為店內人員，不再被當成客人。
  - 原因 2：購買面板沒檢查按的人是不是工單客人，店長在客人的工單裡按商品按鈕，訂單就記成店長的。現在非工單客人按會被擋下並提示；若工單上記的「客人」其實是店內人員（舊版誤判），客人一按就會自動更正。
  - 新增 `/設定工單客人`：在工單頻道內用，把已經記錯的工單改成正確的客人（同時更正還沒付款的進行中訂單，已用餘額付款的不動）。
- **V162**：清理與修正。
  - 修正：`/暫停接單` 以前只寫入狀態、下單時從來沒檢查，其實沒有擋住任何人；現在幣號、子彈、代肝、不死號洽談與最後建單都會檢查。
  - 修正：`/設定訊息` 的「沒貨提示」「數量不足提示」、`/設定店長公告`、`/設定補貨時間` 以前存了卻沒有任何地方讀取；現在都會顯示。
  - 清理：移除沒用到的函式、合併兩份完全重複的「關閉工單」處理、清掉沒用到的變數與多餘空行。
  - 新增：`/訂單操作紀錄`（操作紀錄一直有寫入，但以前沒有地方可以看）。
  - 測試合併成單一檔案 `test_bot.py`；README 精簡。
- **V161**：餘額付款與取消自動退款、`/匯出資料庫`、低庫存提醒、自動測試；舊資料庫自動補上 `orders.balance_paid`、`orders.balance_refunded` 欄位。
- **V160**：`/餘額紀錄`、`/餘額總覽`、加扣餘額備註與上限、`/查詢餘額` 權限提示。
- **V159**：自訂訊息防呆（多餘大括號不再讓付款頁報錯）、付款提醒迴圈不再因例外停止、狀態按鈕防呆（舊按鈕不能把訂單改回去）、資料庫每 6 小時自動備份。
- **V158**：`/發號` 的登入方式改為選填，沒選就從庫存足夠的登入方式中隨機挑一種。
- **V157**：取消或結單時退回預扣庫存；`admin()` 不再把「管理頻道」權限當管理員，餘額與匯出入改用 `strict_admin()`；`/匯入設定` 新增「覆蓋庫存與餘額」選項（預設否）；代肝帳號只收看起來像帳號的訊息。
